# 00 — תוכנית בנייה: אתר מסד ידע ללמידה (end-to-end)

מסמך זה הוא נקודת הכניסה עבור **Claude Code**. הוא מתאר איך לבנות מאפס אתר למידה אישי, מקצועי ופרוס (deployed), המבוסס על מסד הידע הקיים של קורס AI Engineer (מחזור 6).

## מה בונים
אתר למידה אישי (PWA) עם 160 נושאים ב־5 מודולים, שמאפשר עיון, חיפוש, סינון, וכלי למידה אקטיביים (התקדמות, כרטיסיות, מבחן, הערות). האתר עובד אופליין, ניתן להתקנה על הטלפון, ומסנכרן נתונים אישיים בין מכשירים דרך בקאנד קל (Supabase).

## החלטות שכבר התקבלו (אל תשנה בלי לשאול)
- **בנייה נקייה מחדש** — פרויקט מסודר וניתן לתחזוקה, לא עטיפה של קובץ ה־HTML הקיים.
- **בקאנד קל לסנכרון** — Supabase (Auth + Postgres + RLS). אין שרת מותאם לתחזק.
- **משתמש יחיד** בפועל (Gil), אבל הארכיטקטורה תומכת ריבוי משתמשים דרך Auth.
- **התוכן (`TOPICS`) נשמר כפי שהוא** — אין לשנות הגדרות/תוכן של נושאים.

## חבילת המסמכים (סדר קריאה)
1. `00-BUILD-README.md` — המסמך הזה: סקירה, סדר בנייה, הגדרת "בוצע".
2. `01-ARCHITECTURE-AND-STACK.md` — stack, מבנה תיקיות, החלטות טכניות ונימוקים.
3. `02-DATA-MODEL-AND-MIGRATION.md` — סכימת הנתונים והמרת הדאטה הקיים (כולל טיפול בתמונות המוטמעות).
4. `03-FRONTEND-SPEC.md` — רכיבים, פיצ'רים (קיימים + חדשים), design system, נגישות.
5. `04-BACKEND-SUPABASE-SYNC.md` — סכימת DB, Auth, מדיניות RLS, אסטרטגיית סנכרון local-first.
6. `05-PWA-AND-DEPLOYMENT.md` — manifest, service worker, offline, אירוח ו־CI.
7. `CLAUDE.md` — קובץ הנחיות להטמעה בשורש הריפו (קונבנציות, פקודות, גבולות).

## הדאטה המצורף
- `data/topics.raw.json` — **160 הנושאים האמיתיים** שחולצו מהקובץ הקיים (7.9MB, כולל HTML ותמונות base64 מוטמעות). זהו מקור האמת לתוכן.
- `data/modules.json` — 5 המודולים ותוויות התצוגה שלהם.

> ⚠️ `topics.raw.json` גדול כי 90 מתוך 160 הנושאים מכילים תמונות base64 מוטמעות בתוך `content_html` (ממוצע 41KB לנושא). שלב המיגרציה (מסמך 02) מפרק אותן לקבצים — **אל תשלח את ה־raw כמות שהוא ל־frontend**.

## סדר בנייה מומלץ (אבני דרך)

**Phase 0 — תשתית (יום 1):**
אתחול הפרויקט (Vite + React + TS), מבנה תיקיות, Tailwind/tokens, ESLint/Prettier, git. → *build עובר, דף ריק עולה.*

**Phase 1 — מיגרציית דאטה (יום 1–2):**
סקריפט שמפרק את `topics.raw.json`: מחלץ תמונות base64 לקבצים, מנקה, ומייצר `topics.clean.json` + אינדקס חיפוש. → *דאטה קליל ומובנה מוכן לצריכה.*

**Phase 2 — Frontend ליבה (יום 2–4):**
כל מה שקיים היום + תיקוני ה־P0: header/hero/sidebar, חיפוש, סינון מרובה, accordion, מיון, רשת/רשימה, קורא, נוסחאות KaTeX, ערכות נושא, **הצללות/עומק, `focus-visible`, ניווט מקלדת מלא**. → *אתר עיון מלוטש ומלא.*

**Phase 3 — כלי למידה מקומיים (יום 4–6):**
מעקב התקדמות, מועדפים, "נצפו לאחרונה", הערות אישיות, כרטיסיות + חזרה מרווחת, מצב מבחן, command palette. הכול נשמר מקומית (IndexedDB). → *כלי למידה אמיתי, עובד גם בלי חשבון.*

**Phase 4 — PWA + Offline (יום 6):**
manifest, service worker, caching, התקנה על מובייל. → *אפליקציה שאפשר להתקין ולעבוד בה אופליין.*

**Phase 5 — בקאנד + סנכרון (יום 7–8):**
Supabase: Auth, טבלאות, RLS, סנכרון local-first (IndexedDB ↔ ענן). → *נתונים אישיים עוברים בין טלפון למחשב.*

**Phase 6 — Deploy (יום 8):**
פריסה ל־Cloudflare Pages / Netlify, משתני סביבה, דומיין, בדיקות. → *האתר חי ונגיש מכל מקום.*

## הגדרת "בוצע" (Definition of Done) לכל שלב
כל שלב חייב: build ירוק, בדיקה ידנית בבהיר+כהה, RTL תקין, נגישות מקלדת עובדת, ואין רגרסיה בפיצ'רים קודמים. שלבים 2+ כוללים בדיקה במובייל.

## עקרונות־על
- **Local-first:** האתר עובד במלואו בלי חשבון ובלי רשת. הבקאנד הוא שכבת סנכרון אופציונלית, לא תלות.
- **התוכן קדוש:** אין לגעת בטקסט/הגדרות של הנושאים; רק במבנה, בעיצוב ובאינטראקציה.
- **פשטות תחזוקה:** בלי שרת מותאם, בלי תלויות כבדות מיותרות, נתונים מופרדים מקוד.
