📋 הגדרה

CrewAI Flows הם דרך מובנית לבנות workflows רב-שלביים מבוססי-אירועים, המתאמים בין tasks ו-Crews. Flows מנהלים סדר ביצוע, state ולוגיקה, ומאפשרים אוטומציות AI גמישות וניתנות להרחבה.

🏛️ יכולות מפתח

  • Workflow Orchestration — שרשור מספר tasks ו-Crews בצורה חלקה.
  • State Management — שיתוף ושימור state בין שלבים, באמצעות dict גמיש או מודל Pydantic מבני.
  • Event-Driven Design — תגובה דינמית ל-triggers ואירועים, באמצעות decorators: @start(), @listen(), @router().
  • Flexible Control Flow — תנאים, לופים, ו-branching מובנים (or_, and_, @router()).

⚙️ Decorators מרכזיים

Decoratorתפקיד
@start()מסמן את שלב הפתיחה של ה-Flow
@listen(method)מריץ method כשה-method שהוא מאזין לו מסתיים
@router(method)מנתב לתנאים שונים לפי הפלט של method
or_(m1, m2)מאזין למספר methods, מופעל כשאחד מהם מסתיים
and_(m1, m2)מאזין למספר methods, מופעל רק כששניהם הסתיימו

💻 קוד לדוגמה — Flow פשוט עם Router

from crewai.flow.flow import Flow, start, listen, router
import random
class RouterFlow(Flow):
@start()
def start_method(self):
self.state[&quot;success_flag&quot;] = random.choice([True, False])
@router(start_method)
def second_method(self):
return &quot;success&quot; if self.state[&quot;success_flag&quot;] else &quot;failed&quot;
@listen(&quot;success&quot;)
def third_method(self):
print(&quot;Third method running&quot;)
@listen(&quot;failed&quot;)
def fourth_method(self):
print(&quot;Fourth method running&quot;)

🧠 שאלות ראיון נפוצות

ש: מה ההבדל בין or_ ל-and_ ב-CrewAI Flows?

ת: or_(m1, m2) מפעיל את ה-listener כאשר אחת מהשיטות מסתיימת (הראשונה שמסתיימת מפעילה); and_(m1, m2) ממתין ששתי השיטות יסתיימו לפני הפעלת ה-listener.

ש: מתי תשלב Hierarchical ו-Sequential Crews בתוך אותו Flow?

ת: כשחלק מהתהליך דורש בקרת איכות ותיאום בין מספר תפקידים מתמחים (שלב מחקר/כתיבה עם manager) וחלק אחר הוא שרשרת לינארית פשוטה (ערכית/בדיקה) שלא דורשת ניהול — Flow מאפשר לשלב את שני סוגי ה-Process באותו pipeline.
