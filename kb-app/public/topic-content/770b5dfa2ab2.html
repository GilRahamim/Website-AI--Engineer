📋 הגדרה

Agent מבוסס-ReAct יכול לבצע נימוק איטרטיבי מעל Knowledge Graph: בכל שלב הוא בוחן אם יש לו מספיק עדות, קורא לכלי חיפוש-גרף, קורא את התוצאה, ומחליט אם להמשיך לחקור entity-גשר (bridge entity) חדש שהתגלה. כך ה-agent "קופץ" בין ישויות (multi-hop) עד שמגיע לתשובה מלאה.

🏛️ זרימת העבודה (Full Demo Architecture)

User Query → LLM (ReAct reasoning) → Tool call → Neo4j → Graph results → LLM מחליט את השלב הבא → (חזרה לכלי או) → Final Answer.

⚙️ לופ ReAct מקומי — צעד אחר צעד

  • Thought — האם יש כבר מספיק עדות לענות?
  • Action — קריאה ל-graph_search_tool עם המוקד (focus) הנוכחי.
  • Observation — קריאת תוצאת הכלי.
  • Thought — האם ה-observation חשף entity-גשר חדש ששווה לחקור? אם כן — להגדיר focus חדש ולחזור ללופ; אם לא — לעצור.

💻 קוד לדוגמה — ReAct מקומי עם כלי גרף

def local_react_agent(query: str, max_steps: int = 2) -&gt; dict:
&quot;&quot;&quot;Iterative ReAct loop: think, act, observe, decide whether to act again.&quot;&quot;&quot;
trace, evidence, explored = [], [], set()
current_focus = query
for step in range(1, max_steps + 1):
trace.append({&quot;step&quot;: &quot;Thought&quot;,
&quot;content&quot;: f&quot;Step {step}: current focus is {current_focus!r}.&quot;})
observation = graph_search_tool(current_focus)
# Thought: does observation surface a new bridge entity worth exploring?
# If yes -&gt; current_focus = bridge_entity; loop. If no -&gt; stop.
return {&quot;trace&quot;: trace, &quot;evidence&quot;: evidence}

🎯 שימושים עיקריים

  • שאלות חיתוך/קישוריות בין שתי קבוצות ישויות ("מי מספק לשני יצרנים?").
  • שילוב כלי open-ended exploration (graph traversal) עם כלי factual lookup (text-to-Cypher) באותו agent, לפי אופי השאלה.

✅ יתרונות

  • ה-agent יכול לעקוב אחר entity-גשר שמתגלה בזמן ריצה — לא תלוי בנתיב מוגדר מראש.
  • שילוב שני כלים (graph_search + cypher_query) מאפשר גמישות בין חקירה פתוחה לשאילתה מדויקת.

❌ מגבלות

  • מספר צעדים מקסימלי (max_steps/max_hops) נדרש כדי למנוע לופים אינסופיים.
  • תלוי באיכות הכלים (seed entity matching, Cypher generation) — שגיאה בשלב מוקדם מתפשטת.

🧠 שאלות ראיון נפוצות

ש: מה ההבדל בין neo4j_graph_search ל-neo4j_cypher_query כשני כלים נפרדים?

ת: neo4j_graph_search מתאים לחקירה פתוחה ("מה מחובר ל-X?") ומחזיר קשתות תומכות גולמיות; neo4j_cypher_query מתאים לשאלות עובדתיות ספציפיות ("מי מספק X?") ומתרגם לשאילתת Cypher מדויקת ומחזיר תשובה ישירה.

ש: איך ה-agent יודע מתי להמשיך לחקור entity-גשר חדש?

ת: בשלב ה-Thought השני בכל איטרציה, ה-agent בוחן את ה-observation שהתקבל ומזהה אם הוא מכיל ישות בעלת מעלה (degree) גבוהה או רלוונטיות לשאלה המקורית; אם כן הוא מעדכן את current_focus לישות זו וממשיך ללופ.
