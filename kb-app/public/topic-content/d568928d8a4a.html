📋 הגדרה

משימה של זיהוי רשומות (records) שונות, אשר מתארות את אותה ישות בעולם האמיתי (אדם, חברה, מוצר) אך נכתבו בצורה שונה — עקב שגיאות כתיב, פורמטים שונים, או חסר מידע. המטרה: לאחד/לקשר רשומות אלה (Deduplication).

🔍 מתי זה קורה?

  • איחוד מסדי נתונים ממקורות שונים (CRM, מסדי לקוחות, רשימות דיוור).
  • ניקוי דאטה לפני אימון מודל — מניעת כפילויות שמטות את ההתפלגות.
  • התאמת רשומות חיצוניות (לדוגמה רשימת ספקים) לרשומות פנים-ארגוניות.

⚠️ איך מזהים בעיה?

  • אותה ישות מופיעה כמה פעמים בדאטה בכתיב שונה (לדוגמה: "Jon Smith" לעומת "John Smith").
  • שמות חברה עם הבדלי קיצור/פיסוק ("IBM" לעומת "I.B.M.").
  • כתובות/שמות עם שגיאות הקלדה, רישום חלקי או סדר שונה של שדות.

🛠️ איך פותרים / מטפלים?

  • Preprocessing / נורמליזציה: אותיות קטנות, הסרת פיסוק, הסרת רווחים מיותרים, תקנון פורמטים (תאריכים, מספרי טלפון).
  • חישוב דמיון בין מחרוזות: Fuzzy String Matching מבוסס Edit Distance (Levenshtein), או דמיון n-gram + TF-IDF + Cosine לקנה מידה גדול.
  • קביעת סף דמיון (threshold) להחלטה אם שתי רשומות מתארות את אותה ישות.
  • לעיתים נדרש שלב Blocking — חלוקה לקבוצות מועמדות לפני ההשוואה, כדי להימנע מהשוואת כל זוג רשומות (סקיילביליות).

🔄 קשר לנושאים אחרים

Record Linkage מתבסס ישירות על Fuzzy String Matching לחישוב הדמיון בין מחרוזות, ולעיתים גם על Jaccard Similarity (השוואת קבוצות n-grams). בקנה מידה גדול נעזרים בייצוג character n-gram + TF-IDF + Cosine Similarity כדי להפוך את ההשוואה לסקיילבילית.

🧠 שאלות ראיון נפוצות

ש: מה ההבדל בין Record Linkage לבין Deduplication?

ת: Deduplication הוא מקרה פרטי של Record Linkage — זיהוי כפילויות בתוך מקור נתונים אחד, בעוד Record Linkage כללי יותר ועוסק גם בקישור בין מקורות שונים.

ש: מדוע השוואת כל זוגות הרשומות (Brute Force) אינה סקיילבילית?

ת: מספר הזוגות גדל ביחס ריבועי למספר הרשומות; לכן משתמשים בשלבי Blocking או בייצוג וקטורי + Cosine Similarity לסינון מועמדים מהיר.
