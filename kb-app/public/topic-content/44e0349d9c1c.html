הגדרה

ספריית החישוב המספרי שעליה בנוי כל הסטאק של מדעי הנתונים ב-Python. הרעיון המרכזי הוא ה-ndarray — מערך רב-ממדי הומוגני שנשמר כבלוק רציף בזיכרון, מה שמאפשר פעולות וקטוריות מהירות בלי לולאות Python. Pandas, scikit-learn ו-PyTorch כולם עומדים על המבנה הזה.

למה לא פשוט רשימות Python?

  • רשימה מחזיקה מצביעים לאובייקטים מפוזרים בזיכרון; ndarray מחזיק את הנתונים עצמם ברצף — גישה מהירה בהרבה.
  • פעולות על ndarray מתבצעות בקוד C מהודר (vectorization) במקום בלולאת Python — שיפור של סדר גודל ויותר.
  • רשימה יכולה לערבב טיפוסים; מערך הוא הומוגני, ולכן אפשר לדעת מראש כמה בתים כל איבר תופס.
  • Broadcasting מאפשר פעולות בין מערכים בגדלים שונים בלי לשכפל דאטה.

תכונות ושינוי צורה

  • arr.shape — הממדים. זו התכונה שתבדוק הכי הרבה פעמים בדיבאג.
  • arr.dtype — טיפוס הנתונים (int64, float64 וכו').
  • arr.reshape(rows, cols) — שינוי צורה. מכפלת הממדים החדשים חייבת להיות שווה למספר האיברים הקיים.
  • arr.max() / arr.min() — ערכי קיצון; argmax() / argmin() מחזירים את המיקום שלהם ולא את הערך.

אינדוקס ופריסה

  • חד-ממדי: arr[3], arr[1:5], arr[::2] — בדיוק כמו רשימות.
  • דו-ממדי: arr[row, col] — הפסיק מפריד בין הצירים. arr[1][2] עובד אבל איטי יותר ופחות קריא.
  • פריסה דו-ממדית: arr[0:2, 1:3] — שורות ואז עמודות.
  • השמה משודרת: arr[0:3] = 50 מציב את הערך בכל התאים בבת אחת.
  • בחירה בוליאנית: arr[arr > 5]. הביטוי arr > 5 מחזיר מערך של True/False שמשמש כמסכה.

המלכודת המרכזית — View לעומת Copy

פריסה של מערך NumPy אינה יוצרת עותק אלא מחזירה חלון על אותו בלוק זיכרון. שינוי בפריסה משנה את המערך המקורי. זו ההתנהגות שמייצרת את רוב הבאגים הסמויים בקוד NumPy של מתחילים. אם צריך עותק עצמאי, יש לבקש אותו במפורש עם arr.copy().

פעולות ופונקציות אוניברסליות

כל האופרטורים האריתמטיים פועלים איבר-איבר:

arr + arr        # חיבור איבר-איבר
arr * arr        # כפל איבר-איבר, לא כפל מטריצות
arr @ arr        # זה כפל מטריצות
arr ** 2
arr / arr        # 0/0 -> nan (עם אזהרה), 1/0 -> inf

np.sqrt(arr)     # שורש
np.exp(arr)      # e בחזקת x
np.log(arr)      # לוגריתם טבעי
np.sin(arr)      # פונקציות טריגונומטריות
arr.sum(axis=0)  # סכום לפי עמודות; axis=1 לפי שורות

חלוקה באפס אינה זורקת חריגה: 0/0 מחזיר nan ו-1/0 מחזיר inf, בליווי RuntimeWarning. הערכים האלה ימשיכו להתפשט בחישוב ויהרסו אותו בשקט — כדאי לבדוק אותם עם np.isnan.

קוד לדוגמה

import numpy as np

arr = np.arange(0, 11)              # [0 1 2 ... 10]
mat = np.arange(16).reshape(4, 4)   # מטריצה 4x4

print(mat.shape, mat.dtype)         # (4, 4) int64
print(mat[1:3, 1:3])                # [[5 6] [9 10]]
print(arr[arr > 5])                 # [6 7 8 9 10]

# View מול Copy
slice_of_arr = arr[0:5]
slice_of_arr[:] = 99
print(arr)                          # arr השתנה!

safe = arr.copy()[0:5]
safe[:] = 0
print(arr)                          # arr לא נגע

# סטטיסטיקה לפי ציר
print(mat.mean(axis=0))             # ממוצע לכל עמודה
print(mat.sum(axis=1))              # סכום לכל שורה

שאלות ראיון נפוצות

ש: למה NumPy מהיר יותר מרשימות Python?

ת: שתי סיבות. ראשית, הנתונים שמורים כבלוק רציף בזיכרון עם טיפוס אחיד, בעוד שרשימה מחזיקה מצביעים לאובייקטים מפוזרים. שנית, הפעולות מתבצעות בקוד C מהודר על כל המערך בבת אחת (vectorization) במקום בלולאת Python שמפרשת כל איטרציה מחדש.

ש: מה ההבדל בין arr[1:3] ל-arr[1:3].copy()?

ת: הראשון מחזיר view — חלון על אותו זיכרון, ושינוי בו משנה את המערך המקורי. השני מקצה זיכרון חדש ומעתיק את הנתונים, כך שהשינויים מבודדים. NumPy בוחר ב-view כברירת מחדל מטעמי ביצועים.

ש: מה ההבדל בין arr * arr ל-arr @ arr?

ת: הכוכבית היא כפל איבר-איבר (Hadamard); הסימן @ הוא כפל מטריצות אמיתי. זו טעות נפוצה כשעוברים מנוסחה מתמטית לקוד.
