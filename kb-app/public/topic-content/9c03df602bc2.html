📋 הגדרה

Hook הוא פקודת shell שה-runtime מפעיל באירוע מחזור-חיים (lifecycle event) מסוים — ופועל תמיד, באופן דטרמיניסטי, ללא תלות בהחלטת המודל. קוד היציאה (exit code) והפלט (stdout) קובעים מה קורה בהמשך (לדוגמה: לחסום קריאת כלי).

🔍 הבעיה שזה פותר

מודלי LLM הם non-deterministic — אי אפשר לסמוך על מודל ש'יזכור' להריץ lint, לחסום rm -rf, או לפרמט קוד בכל פעם. Hooks מספקים אכיפה מובטחת, מחוץ לשליטת המודל.

⚙️ אירועי Hook עיקריים

אירועתפקיד
PreToolUseבדיקה או חסימה של קריאת כלי לפני הביצוע
PostToolUseתגובה לתוצאות (פרמוט, lint, לוג)
UserPromptSubmitהזרקת קונטקסט, או דחיית פרומפטים
SessionStart / Stop / Notificationניהול ותחזוקה (bookkeeping)

מוגדרים בקובץ .claude/settings.json או באמצעות אופציית hooks ב-SDK.

💻 קוד לדוגמה — חסימת Bash מסוכן + פרמוט אוטומטי

# .claude/settings.json
{
&quot;hooks&quot;: {
&quot;PreToolUse&quot;: [{
&quot;matcher&quot;: &quot;Bash&quot;,
&quot;hooks&quot;: [{ &quot;type&quot;: &quot;command&quot;, &quot;command&quot;: &quot;./scripts/guard_bash.sh&quot; }]
}],
&quot;PostToolUse&quot;: [{
&quot;matcher&quot;: &quot;Edit|Write&quot;,
&quot;hooks&quot;: [{ &quot;type&quot;: &quot;command&quot;,
&quot;command&quot;: &quot;prettier --write $CLAUDE_FILE_PATH&quot; }]
}]
}
}
# scripts/guard_bash.sh  — exit 2 blocks the tool call
jq -r '.tool_input.command' | grep -Eq 'rm -rf /|:(\)\{' &amp;&amp; exit 2

🛠️ עקרונות עבודה (best practice / anti-pattern)

  • Hooks הם שומרים (guards), לא features — לא להטמיע בהם לוגיקה עסקית מורכבת.
  • לשמור אותם קצרים ו-idempotent (הרצה חזרתית לא משנה תוצאה).
  • דוגמה ל-deterministic gate: hook מסוג PreToolUse שמריץ typecheck לפני כל Edit — חוסם commits שבורים.

✅ יתרונות

  • אכיפה מובטחת — לא תלוי בזיכרון/ציות של המודל.
  • חוצה את כל שכבות ה-stack (plugin, skill, sub-agent, tool) — guardrail אחיד.

❌ מגבלות

  • אם hook מכיל לוגיקה כבדה/לא-אידמפוטנטית — עלול לגרום לתופעות לוואי בלתי צפויות.
  • לא מתאים לקבלת החלטות 'חכמות' — Hooks הם שכבת כפייה (enforcement), לא הסקה (reasoning).

🧠 שאלות ראיון נפוצות

ש: מדוע אסור לסמוך על system prompt בלבד כדי למנוע פקודת rm -rf / מסוכנת?

ת: כי system prompt הוא הנחיה למודל non-deterministic — המודל יכול 'לשכוח' או לפרש לא נכון תחת לחץ הקשר. Hook מסוג PreToolUse רץ כקוד שמחוץ למודל ובודק/חוסם תמיד, ללא תלות בהחלטת המודל.

ש: מה ההבדל בין PreToolUse ל-PostToolUse hook?

ת: PreToolUse רץ לפני ביצוע הכלי ויכול לחסום אותו (exit code 2 חוסם); PostToolUse רץ אחרי התוצאה ומשמש לתגובה — פרמוט, lint, לוג — אך לא יכול למנוע את הביצוע שכבר קרה.
