📋 הגדרה

שני מדדי הערכה סטנדרטיים למערכות אחזור/דירוג (Retrieval/Ranking): Recall@K בודק כמה מהתוצאות הרלוונטיות אותרו בתוך K התוצאות המובילות, ו-MRR (Mean Reciprocal Rank) בודק באיזה מיקום ממוקמת התוצאה הרלוונטית הראשונה, בממוצע על פני שאילתות.

✅ מתי עדיף על מדדים אחרים?

  • Recall@K מתאים כשמעניינות אותנו כל התוצאות הרלוונטיות בתוך חלון תוצאות נתון (לדוגמה — חלון ה-Retrieval לפני re-ranking ב-RAG).
  • MRR מתאים כשיש בדרך כלל תשובה נכונה אחת ומעניין מתי היא מופיעה לראשונה (לדוגמה — מנוע חיפוש שמציג תוצאה אחת בעיקר).

❌ מגבלות

  • שני המדדים דורשים Ground Truth — צריך לדעת מראש מהן התשובות הנכונות, גם כאשר המודל עצמו הוא Unsupervised.
  • MRR מתמקד רק בתוצאה הרלוונטית הראשונה ומתעלם משאר התוצאות הרלוונטיות.
  • Recall@K אינו מתחשב בסדר הפנימי של התוצאות בתוך top-K (בניגוד למדדים כמו NDCG).

💻 מימוש בקוד

def recall_at_k(retrieved, relevant, k):
top_k = set(retrieved[:k])
return len(top_k &amp; set(relevant)) / len(relevant)
def mrr(rank_list):
# rank_list: rank of first relevant result per query
return sum(1.0 / r for r in rank_list) / len(rank_list)

🧠 שאלות ראיון נפוצות

ש: אם נמצאו 3 מתוך 4 תוצאות רלוונטיות בתוך top-10, מה Recall@10?

ת: 3/4 = 0.75.

ש: מה ההבדל בין Recall@K ל-MRR מבחינת מה שהם מודדים?

ת: Recall@K מודד שלמות (כמה תוצאות רלוונטיות נמצאו), בעוד MRR מודד מיקום (כמה מהר הופיעה התשובה הנכונה הראשונה).
