📋 הגדרה

AI Agent הוא מערכת מבוססת-LLM שמתכננת, מנמקת (reasoning) ופועלת (acting) באופן אוטונומי להשגת מטרה — בניגוד ל-pipeline נוקשה עם שלבים קבועים-מראש, ה-agent מפרק משימה כוללת לצעדים, ומשתמש בכלים/זיכרון לפי הצורך.

🔍 Agentic Workflow מול one-shot prompt

One-shot prompt: קלט → LLM → פלט, ללא איטרציה. Agentic workflow: המשימה מפורקת לשלבי Thinking/Research → Revise → Finish, עם איטרציות וקריאות כלים בין לבין. לדוגמה, תכנון חופשת סקי דורש בדיקת ימי חופשה, חיפוש יעדים, בדיקת תחזית מזג אוויר, הזמנת טיסה והזמנת מלון — חמש משימות שLLM רגיל לא יכול לבצע (אין לו גישה ל-API-ים חיצוניים ולנתוני המשתמש).

🏛️ מגבלות LLM רגיל בטיפול בבקשות מורכבות

  • עונה על שאלות גנריות לפי נתוני אימון ציבוריים — לא על נתונים ספציפיים לחברה.
  • אין לו גישה לנתונים עדכניים או ל-API-ים חיצוניים (מזג אוויר היום, הזמנת מלון).
  • עונה רק לפי נתוני אימון עם knowledge cutoff קבוע.

Agentic AI — שימוש בהיגיון מתוחכם ותכנון איטרטיבי לפתרון אוטונומי של בעיות מורכבות ורבות-שלבים, תוך גישה לנתוני ארגון ושימוש בכלים.

🧰 Agent Frameworks — מהי המטרה?

  • ספריות/פלטפורמות עם רכיבים מובנים-מראש לפיתוח agents (ניהול זיכרון, אינטגרציית כלים, תכנון, תקשורת multi-agent).
  • מאפשרות למפתחים להתמקד בלוגיקת ה-agent ולא בפרטי המימוש הנמוכים.
  • יתרונות: פיתוח מהיר יותר, גישות סטנדרטיות, אינטגרציה קלה עם מודלים/כלים שונים, תמיכה בארכיטקטורות שונות (ReAct, multi-agent).

🧠 שאלות ראיון נפוצות

ש: מה ההבדל בין pipeline רגיל ל-AI Agent?

ת: Pipeline מבצע שלבים קבועים-מראש בסדר נתון; Agent מתכנן, מנמק ופועל אוטונומית — מחליט דינמית אילו צעדים/כלים נדרשים כדי להשיג מטרה.

ש: מהם חמשת המרכיבים המרכזיים של ארכיטקטורת AI Agent?

ת: Planning (תכנון), Tools & Action (כלים ופעולה), Memory (זיכרון), Guardrails (גידור בטיחות), Communication (תקשורת בין agents).
