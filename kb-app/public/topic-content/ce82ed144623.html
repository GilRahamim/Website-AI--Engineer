📋 הגדרה

MCP (Model Context Protocol) הוא גישה ארכיטקטונית המפרידה (decouple) בין שכבת ה-UI, שכבת ה-Orchestration ושכבת ה-Execution של agent. ההפרדה הזו משפרת תחזוקתיות, סקלאביליות, תצפיתיות (observability) ופריסה מאובטחת. ניתן לחשוב על MCP כ"מתאם אוניברסלי" — במקום לבנות אינטגרציה מותאמת לכל שירות (DB, API, קבצים), MCP מספק פרוטוקול אחד אחיד.

🏛️ שלוש שכבות הארכיטקטורה

שכבהתיאורטכנולוגיות נפוצות
Client (Frontend)ה-UI שבו המשתמש מתקשר (chat/form/dashboard). קורא ל-API של ה-backend ומציג תשובות. אופציונלי: WebSocket לסטרימינג.Angular, React, Vue
Processing (Backend/Orchestration)חושף API endpoints, מתאם לוגיקת agent (ניתוב שאילתות לכלי/agent הנכון), מטפל בהפעלת כלים, תכנון וביצוע, לוגים ומדדים, caching/session memory.FastAPI, Flask
LLM/Execution Layerמטפל בקריאות ה-LLM בפועל ובלוגיקת function calling/tool invocation. כולל code execution agents, retrieval (vector DB ל-RAG), וקריאות API חיצוניות.OpenAI, Claude, Gemini

🎯 תחומי שימוש

  • Modularity & Separation of Concerns — הפרדת UI, orchestration ו-LLM משפרת סקלאביליות ותחזוקתיות.
  • Multi-Agent Ecosystem — שרתי MCP משתלבים בקלות עם CrewAI, LangChain, AutoGen.
  • Production-Oriented — מאפשר authentication, logging, rate-limiting ו-monitoring מהיום הראשון.

✅ יתרונות

  • פרוטוקול אחד עקבי במקום אינטגרציות מותאמות לכל שירות.
  • כל agent הוא microservice מודולרי עם schema קלט/פלט מוגדר היטב.
  • ניתן להתחיל קטן (agent/tool אחד) ולהתרחב לזרימות multi-agent מתואמות.

❌ מגבלות

  • מוסיף שכבת תשתית/תיאום נוספת בהשוואה לקריאת API ישירה ל-LLM.
  • MCP מגדיר את הפרוטוקול בלבד — לא את הפריימוורק; דורש בחירת כלים לכל שכבה.

🧠 שאלות ראיון נפוצות

ש: מה ההבדל בין MCP לבין שימוש ב-API ישיר של LLM?

ת: MCP מפריד את שכבות ה-UI, ה-orchestration וה-execution לרכיבים נפרדים וניתנים להחלפה, ומאפשר ניהול מרובה-agents, אבטחה, לוגים ותצפיתיות — בניגוד לקריאת API ישירה שמשלבת הכל בקוד אחד.

ש: מדוע MCP מתואר כ"מתאם אוניברסלי"?

ת: כי הוא מספק פרוטוקול תקשורת אחד עקבי בין agents/LLM לכלים חיצוניים (DB, API, קבצים), במקום לדרוש אינטגרציה מותאמת לכל שירות בנפרד.
