הגדרה

Batch Size הוא מספר התצפיות שעליהן מחושב ה-Loss לפני כל עדכון פרמטרים. Epoch הוא מעבר מלא אחד של כל דאטה האימון דרך המודל. שני הפרמטרים האלה קובעים יחד כמה עדכוני פרמטרים מתבצעים באימון וכמה זיכרון הוא צורך.

שלוש שיטות העדכון

  • Stochastic GD — batch size = 1. כל עדכון מחושב על תצפית אחת בלבד. השיטה ה``רועשת'' ביותר: כל תצפית מזיזה את הפרמטרים לכיוון שלה.
  • Mini-Batch SGD — batch size = k (למשל 16, 32, 64). פשרה בין שתי הקיצוניות, וזו השיטה הנפוצה ביותר בפועל.
  • Full Batch GD — batch size = N, כל הדאטה. עדכון אחד לפי הממוצע על כל התצפיות. הכי פחות רועש, אך לא בהכרח הכי טוב.

הקשר בין Batch ל-Epoch

דוגמה: 1000 תצפיות עם batch size של 100 — epoch אחד שווה 10 עדכוני פרמטרים.

נקודה פרקטית קריטית — זיכרון

Batch Size הוא הפרמטר הכי משפיע על ביצועי החומרה: הוא קובע כמה דאטה שמור בזיכרון הפעיל, כולל ה-GPU, בכל רגע. בחירה גרועה תגרום ל-CUDA out of memory או לקריסת Python. ערכים נפוצים: 8, 16, 32, 64. תמיד לוודא שהמודל בכלל רץ לפני שמתחילים לכייל ביצועים.

ערבוב אקראי של ה-Batches

לפני החלוקה ל-batches חובה לערבב את התצפיות. אם הדאטה מגיע ממוין לפי קטגוריה, כל batch יכיל רק סוג אחד ויגרום להטיה חמורה בתהליך האימון. ב-PyTorch, DataLoader עם shuffle=True מטפל בזה אוטומטית.

קוד לדוגמה (PyTorch)

from torch.utils.data import DataLoader

BATCH_SIZE = 32
train_loader = DataLoader(train_ds, batch_size=BATCH_SIZE,
                          shuffle=True,      # קריטי — מונע הטיה מדאטה ממוין
                          drop_last=False)

print(f"{len(train_ds)} samples / {BATCH_SIZE} = "
      f"{len(train_loader)} updates per epoch")

for epoch in range(EPOCHS):                  # מעבר מלא על כל הדאטה
    for X_batch, y_batch in train_loader:    # עדכון פרמטרים אחד לכל batch
        optimizer.zero_grad()
        loss = criterion(model(X_batch), y_batch)
        loss.backward()
        optimizer.step()

שאלות ראיון נפוצות

ש: מה ההבדל בין batch ל-epoch?

ת: Batch הוא חלק קטן מהדאטה; epoch הוא מעבר אחד שבו כל הדאטה עבר דרך המודל. אם יש 100 תצפיות ו-batch size שווה 5, צריך 20 batches ל-epoch אחד — כלומר 20 עדכוני פרמטרים ב-epoch אחד.

ש: למה בכלל להשתמש ב-batch size של 1 אם הוא כל כך רועש?

ת: בפועל כמעט לא משתמשים בקיצוניות הזו. הסיבה שהיא קיימת היא זיכרון: לא תמיד אפשר להכניס את כל הדאטה בבת אחת. ברגע שמבינים את המגבלה הזו, מתחילים לשחק עם הפרמטר. בפרקטיקה: SGD עם Mini-Batch, או Adam.

ש: איך גודל ה-batch משפיע על קצב הלמידה שצריך לבחור?

ת: batch גדול יותר נותן אומדן גרדיאנט אמין יותר, ולכן מאפשר — ולעיתים דורש — קצב למידה גבוה יותר. כלל אצבע נפוץ: הכפלת ה-batch size מלווה בהכפלת α (linear scaling rule).
