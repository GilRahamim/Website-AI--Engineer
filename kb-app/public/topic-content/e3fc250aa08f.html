📋 הגדרה

תבנית התקשורת של מערכת agents — Agent בודד (Single Agent) מול ארכיטקטורת Supervisor + Agents מתמחים (Multi-Agent) — קובעת עד כמה המערכת modular, ניתנת להרחבה, ועמידה בפני מורכבות גוברת.

🏛️ Single Agent

  • Agent בודד מבוסס-LLM, מבצע task decomposition בעצמו.
  • מנתב לכלים שונים העומדים לרשותו.
  • מתאים ל-use cases פשוטים.

❌ אתגרי Single Agent

  • Agent בודד יכול "להתבלבל" כשהמורכבות עולה.
  • פחות modular — שינוי בשירות אחד יכול להשפיע על תחומים מרובים (כמו ב-monolith לעומת microservices).

🏛️ Supervisor + Specialized Agents (Multi-Agent)

  • Supervisor Agent — מנתב בין agents מתמחים.
  • Specialized Agents — כל אחד עם משימה ספציפית.
  • Tools Calling — כלים נפרדים לכל Agent.
  • Inter-Agent Communication — שיתוף memory בין agents.
  • Guardrails — מיושמים בכל agent / בשכבת ה-supervisor.

🎯 מתי להשתמש

  • Single Agent: משימות צרות, latency קריטי, תחזוקה מינימלית.
  • Multi-Agent: משימות מורכבות הדורשות מספר תחומי מומחיות (research, writing, editing, QA).

🧠 שאלות ראיון נפוצות

ש: למה Multi-Agent עם Supervisor מדומה ל-microservices ולא ל-monolith?

ת: כל Agent מתמחה הוא יחידה עצמאית עם תפקיד מוגדר (כמו service) — שינוי בלוגיקה של agent אחד לא דורש לשנות agents אחרים, בדיוק כמו ששינוי ב-microservice אחד לא דורש redeploy של כל המערכת.

ש: מהו ה-trade-off המרכזי בבחירת Multi-Agent על פני Single Agent?

ת: מודולריות ויכולת התמחות גבוהות יותר, אך במחיר latency ועלות גבוהים יותר עקב תקשורת בין-agent וקריאות LLM מרובות.
