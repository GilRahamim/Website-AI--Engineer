📋 הגדרה

Conversational RAG הוא וריאנט RAG המתוכנן לאינטראקציות רב-תוריות — הוא שומר זיכרון של קלטי המשתמש ותגובות המערכת הקודמות, ומאפשר שיחה טבעית ומודעת-הקשר על פני מספר פניות.

🏛️ איך זה עובד

  • שמירת השיחה הקודמת (שאלות ותשובות) בזיכרון (memory).
  • שילוב השאילתה הנוכחית עם היסטוריית הצ'אט לביצוע ה-retrieval.
  • המסמכים שנשלפו מועברים ל-LLM יחד עם ההקשר לצורך הגנרציה.
  • נפוץ להשתמש ב-ConversationBufferMemory או אובייקטי memory מתקדמים יותר ב-LangChain.

🎯 תחומי שימוש

  • צ'אטבוטים/עוזרים וירטואליים עם שאלות המשך (follow-up).
  • שירות לקוחות, שאלות-תשובה רפואיות, מערכות הוראה (tutoring).
  • כל מקרה בו שמירת הקשר בין פניות קריטית.

✅ יתרונות

  • מאפשר שיחה טבעית עם שאלות המשך מבלי לחזור על ההקשר בכל פעם.
  • מתאים למקרי שימוש מורכבים כמו עוזר רפואי או יועץ משפטי המשתמשים ברצף שאלות.

❌ מגבלות

  • Latency גבוהה — היסטוריית השיחה מגדילה את גודל ההקשר ל-retrieval ול-generation.
  • עלות גבוהה יותר עקב prompts ארוכים יותר וניהול memory.
  • לא מתאים לשאילתות עצמאיות חד-פעמיות (FAQ) ללא צורך בהקשר היסטורי.

💻 קוד לדוגמה

from langchain.chains import ConversationalRetrievalChain
from langchain.memory import ConversationBufferMemory
from langchain_community.vectorstores import FAISS
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_openai import ChatOpenAI
embedding_fn = HuggingFaceEmbeddings(model_name=&quot;all-MiniLM-L6-v2&quot;)
vectorstore = FAISS.from_texts(texts=documents, embedding=embedding_fn)
retriever = vectorstore.as_retriever(search_kwargs={&quot;k&quot;: 3})
llm = ChatOpenAI(model_name=&quot;gpt-3.5-turbo&quot;, temperature=0.3)
memory = ConversationBufferMemory(memory_key=&quot;chat_history&quot;, return_messages=True)
qa_chain = ConversationalRetrievalChain.from_llm(llm=llm, retriever=retriever, memory=memory)
qa_chain.run(&quot;Tell me about Crohn's disease&quot;)
qa_chain.run(&quot;What are the complications?&quot;)   # uses memory of previous turn

🧠 שאלות ראיון נפוצות

ש: מה התפקיד של max_token_limit ב-ConversationSummaryBufferMemory?

ת: הוא מגביל כמה טוקנים של היסטוריה נשמרים לפני שהמערכת מסכמת אוטומטית את השיחה — שומר על latency/עלות צפויים ומונע overflow של חלון ההקשר.

ש: מתי תעדיף Long-term Memory על פני ConversationBufferMemory רגיל?

ת: כשצריך לזכור עובדות/העדפות בין סשנים שונים (לא רק תוך שיחה אחת) — אז שומרים את העובדות במסד וקטורי ושולפים אותן בהמשך, בדומה ל-retrieval רגיל.
