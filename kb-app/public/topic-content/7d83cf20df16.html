📋 הגדרה

RAG היא ארכיטקטורה היברידית המשלבת שני רכיבים: Retriever ששולף מסמכים/chunks רלוונטיים ממסד ידע, ו-Generator (LLM) שמייצר תשובה מעוגנת (grounded) בהתבסס על המסמכים שנשלפו. הוצגה לראשונה על ידי Facebook AI Research (Lewis et al., 2020) במאמר "Retrieval-Augmented Generation for Knowledge-Intensive NLP".

🏛️ מבנה הפייפליין

שלב האינדוקס (Indexing Stage — חד-פעמי / batch):

  • Parse → Chunk → Embed → Store

שלב זמן-הריצה (Runtime Stage — לכל שאילתה):

  • Query → Retrieve → Inject → Generate

⚙️ זרימת השאילתה (Runtime Query Flow)

  1. קבלת שאילתת המשתמש.
  2. הטמעת השאילתה (embedding) באמצעות אותו מודל ששימש לאינדוקס הקורפוס.
  3. חיפוש במסד הווקטורי אחר top-k ה-chunks הרלוונטיים ביותר.
  4. שילוב השאילתה + ה-chunks לתוך prompt מובנה.
  5. העברת ה-prompt ל-LLM ליצירת תשובה מעוגנת.

🎯 למה צריך RAG?

  • LLMs מוגבלים ל-knowledge cutoff — המידע שלהם קפוא מרגע סיום האימון.
  • ארגונים צריכים להשתמש בנתונים פנימיים/חסויים שה-LLM מעולם לא אומן עליהם.
  • LLMs סגורים נוטים ל-hallucination בביטחון רב — בעיה קריטית בדומיינים בסיכון גבוה (רפואה, משפט).

✅ יתרונות

  • תשובות מעוגנות (grounded) — מפחית hallucination ומגביר דיוק עובדתי.
  • אינטגרציה מאובטחת עם ידע פנימי בלי לאמן מחדש את המודל.
  • התאמה אישית (personalization) — הזרקת הקשר ספציפי-משתמש/משימה.

❌ חסרונות / מגבלות

  • תלוי באיכות ה-retrieval — retrieval גרוע מוביל לתשובות שגויות ("garbage in, garbage out").
  • מוסיף latency וסיבוכיות תפעולית בהשוואה ל-LLM "וניל".

💻 קוד לדוגמה — RAG בסיסי

from langchain_community.vectorstores import FAISS
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_openai import OpenAI
embedding_fn = HuggingFaceEmbeddings(model_name=&quot;all-MiniLM-L6-v2&quot;)
vectorstore = FAISS.from_texts(texts=documents, embedding=embedding_fn)
def rag_qa(query: str, k: int = 3) -&gt; str:
docs = vectorstore.similarity_search(query, k=k)
context = &quot;\n&quot;.join(doc.page_content for doc in docs)
llm = OpenAI(temperature=0.3)
prompt = f&quot;Given the following context:\n{context}\n\nAnswer the question: {query}&quot;
return llm(prompt)

🧠 שאלות ראיון נפוצות

ש: מהם שני הרכיבים המרכזיים של RAG, ומה תפקיד כל אחד מהם?

ת: Retriever — שולף מסמכים/chunks רלוונטיים ממסד ידע באמצעות חיפוש סמנטי; Generator (LLM) — מייצר תשובה מעוגנת על בסיס השאילתה והמסמכים שנשלפו.

ש: מתי תבחר RAG על פני Fine-Tuning?

ת: כשהנתונים משתנים תדיר או חסויים, כשצריך דיוק עובדתי גבוה וניתן לבקרה (auditability), וכשלא ניתן/רוצים להימנע מאימון מחדש של המודל.
