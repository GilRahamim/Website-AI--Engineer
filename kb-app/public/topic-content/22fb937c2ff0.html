📋 הגדרה

Multi-hop Retrieval היא טכניקת RAG שבה מענה על שאלה מחייב שרשור של מספר פיסות עדות ממסמכים שונים — מדמה חשיבה צעד-אחר-צעד, כאשר תוצאת ה-retrieval הראשון מכוונת את ה-retrieval הבא.

🔍 מתי זה קורה?

  • שאלה הדורשת שילוב עובדות ממספר מקורות (סיבה-תוצאה, השוואה).
  • מאגרי ידע גדולים או graphs של ידע מבוזר בין מקורות רבים.

⚠️ איך זה עובד

  1. שאילתה ראשונית משמשת ל-retrieval ראשון (hop 1).
  2. ה-LLM קורא את הקשר מה-hop הראשון ומייצר שאלת המשך / מילות מפתח.
  3. השאלה החדשה משמשת ל-retrieval שני (hop 2).
  4. ההקשר המשולב משני ה-hops מועבר ל-generator לתשובה מעוגנת אחת.

🛠️ מתי להשתמש / מתי להימנע

  • להשתמש: שאלות הדורשות שילוב עובדות, knowledge graphs, קורפוסים גדולים עם מידע מבוזר.
  • להימנע: שאלות חד-hop פשוטות, מקרים שדורשים latency מתחת לשנייה (עוזרי קול).

🔄 קשר לנושאים אחרים

Multi-hop Retrieval משלים ReAct + RAG — ReAct מספק את לוגיקת ההחלטה (האם להמשיך ל-hop נוסף), ו-Multi-hop היא הטכניקה הספציפית לשרשור retrieval על פני מספר שלבים.

💻 קוד לדוגמה

from langchain.chains import RetrievalQA
from langchain_openai import ChatOpenAI
qa_chain = RetrievalQA.from_chain_type(llm=llm, retriever=retriever, chain_type=&quot;stuff&quot;)
# Hop 1
first_answer = qa_chain.run(&quot;What legislation affected insulin pricing?&quot;)
# Hop 2 - follow-up derived from hop 1
second_answer = qa_chain.run(&quot;What did the Inflation Reduction Act do in healthcare?&quot;)
# Final synthesis using both hops
final_prompt = f&quot;&quot;&quot;Using this information:
- {first_answer}
- {second_answer}
Summarize how U.S. legislation affected insulin pricing.&quot;&quot;&quot;
final_response = llm.predict(final_prompt)

🧠 שאלות ראיון נפוצות

ש: למה Multi-hop Retrieval נחוץ כשיש Knowledge Graph?

ת: מידע ב-KG מבוזר לעיתים על פני צמתים/קשרים מרובים — תשובה מלאה דורשת לעבור ("hop") בין מספר צמתים, ולא ניתן להשיג אותה ב-retrieval יחיד.

ש: מהו ה-trade-off המרכזי של Multi-hop Retrieval?

ת: דיוק ועומק תשובה גבוהים יותר על חשבון latency ועלות גבוהות — כל hop נוסף מצריך retrieval וקריאת LLM נוספת.
