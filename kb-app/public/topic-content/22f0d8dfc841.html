הגדרה

הניטור והבקרה של צריכת הטוקנים בכל קריאה למודל, ותרגומה לעלות כספית. במערכות RAG ו-Agents זהו אילוץ הנדסי ראשון במעלה: כל וריאנט ארכיטקטוני — Query Rewrite, Conversational RAG, ReAct — מוסיף קריאות LLM ומאריך פרומפטים, והעלות מצטברת מהר.

חישוב העלות

כאשר p מבוטא בדולרים למיליון טוקנים. טוקני פלט יקרים בדרך כלל פי 3–5 מטוקני קלט, ולכן הגבלת אורך התשובה משפיעה יותר ממה שנדמה.

איך מודדים בפועל

  • כל ספק מחזיר usage בתשובה — prompt_tokens ו-completion_tokens.
  • ב-CrewAI רושמים Event Listener שיורש מ-BaseEventListener ומאזין ל-LLMCallCompletedEvent, וכך אוספים טוקנים לכל קריאה בתוך ה-Crew.
  • מגדירים טבלת מחירים MODEL_COSTS (דולר למיליון טוקנים) ומכפילים.
  • מייצאים דוח לכל ריצה — קריאה, מודל, טוקנים, עלות — כדי להשוות בין וריאנטים ארכיטקטוניים על אותה משימה.

אסטרטגיות הקטנת עלות

  • Prompt Caching — חלקים קבועים של הפרומפט מתומחרים בהנחה משמעותית.
  • Model Routing — מודל קטן וזול למשימות פשוטות, מודל גדול רק כשצריך.
  • Reranking — לאחזר top_k גדול מ-vector store זול, ולהעביר ל-LLM רק 3–5 מסמכים אחרי דירוג מחדש.
  • הגבלת max_token_limit בזיכרון השיחה כדי למנוע גדילה בלתי מבוקרת.
  • Chunking נכון — chunks גדולים מדי מבזבזים טוקנים על טקסט לא רלוונטי.
  • Streaming אינו מוזיל, אך משפר את הזמן לטוקן הראשון ואת חוויית המשתמש בעלות זהה.

קוד לדוגמה (CrewAI Event Listener)

from crewai.events import BaseEventListener, LLMCallCompletedEvent

MODEL_COSTS = {
    "gpt-4o-mini":  {"input_per_1m": 0.15, "output_per_1m": 0.60},
    "gpt-4.1-mini": {"input_per_1m": 0.80, "output_per_1m": 3.20},
}

class CostTracker(BaseEventListener):
    def __init__(self):
        super().__init__()
        self.calls, self.total_usd = [], 0.0

    def setup_listeners(self, crewai_event_bus):
        @crewai_event_bus.on(LLMCallCompletedEvent)
        def on_llm_call(source, event):
            usage = getattr(event, "usage", None) or {}
            t_in  = usage.get("prompt_tokens", 0)
            t_out = usage.get("completion_tokens", 0)
            price = MODEL_COSTS.get(event.model, {})
            usd   = (t_in  / 1e6) * price.get("input_per_1m", 0) + \
                    (t_out / 1e6) * price.get("output_per_1m", 0)
            self.total_usd += usd
            self.calls.append({"model": event.model, "in": t_in,
                               "out": t_out, "usd": round(usd, 6)})

tracker = CostTracker()
crew.kickoff()
print(f"{len(tracker.calls)} LLM calls, total ${tracker.total_usd:.4f}")

שאלות ראיון נפוצות

ש: איפה מתחילים כשעלות מערכת RAG בפרודקשן גבוהה מדי?

ת: מודדים קודם. ברוב המערכות הרכיב הדומיננטי הוא ה-chunks שאוחזרו: top_k כפול chunk_size נכנס לכל בקשה. הקטנת top_k בשילוב Reranker, ו-Prompt Caching על ה-system prompt, נותנות בדרך כלל את החיסכון הגדול ביותר במאמץ הקטן ביותר.

ש: למה טוקני פלט יקרים יותר מטוקני קלט?

ת: טוקני קלט מעובדים במקביל במעבר אחד (prefill), בעוד שכל טוקן פלט דורש מעבר forward נפרד דרך המודל (decode). זה תהליך סדרתי שאינו מקבילי, ולכן יקר יותר לספק.

ש: איך משווים עלות בין שתי ארכיטקטורות?

ת: מריצים את שתיהן על אותו סט שאילתות, אוספים usage לכל קריאה, ומשווים עלות ממוצעת לשאילתה לצד מדדי איכות — Faithfulness, Recall@k. ארכיטקטורה יקרה יותר מוצדקת רק אם היא משפרת את האיכות משמעותית.
