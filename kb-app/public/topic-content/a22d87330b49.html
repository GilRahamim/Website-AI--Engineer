📋 הגדרה

מסגרת מעשית לבחירת התבנית ההנדסית המתאימה למשימת AI נתונה. במקום לקפוץ ישר ל-Agent או RAG, המסגרת ממליצה לבדוק תחילה אם פתרון פשוט יותר מספיק — ולעלות במורכבות רק כשהמשימה דורשת זאת.

⚙️ שמונה התבניות

  • Simple LLM Call — קריאה בודדת למודל, בלי כלים ובלי שליפת מידע חיצוני.
  • RAG — שליפת מידע רלוונטי ממאגר ידע חיצוני לפני יצירת התשובה.
  • Single Agent — מודל עם גישה לכלים (tools) ויכולת תכנון/לולאת פעולה.
  • Multi-Agent — מספר agents מתמחים המשתפים פעולה על משימה מורכבת.
  • Flow / Pipeline קבוע — רצף שלבים דטרמיניסטי שבו ה-LLM הוא רק שלב אחד מתוך תהליך מוגדר.
  • Skill — חבילת ידע/קוד הניתנת לטעינה דינמית (Progressive Disclosure) במקום הטענה מתמדת ב-prompt.
  • Fine-Tuning — אימון נוסף של המודל עצמו כשהתנהגות/סטייל קבועים נדרשים בעקביות.
  • MCP — חיבור סטנדרטי בין מודל לכלים/מקורות מידע חיצוניים בפרוטוקול משותף.

🛠️ איך בוחרים?

  1. האם המשימה דורשת ידע עדכני/חיצוני שלא במשקלי המודל? אם כן — RAG.
  2. האם נדרשת החלטה רב-שלבית עם כלים ולולאת תיקון? אם כן — Agent (יחיד או מרובה).
  3. האם התהליך קבוע וניתן לתיאור כצעדים דטרמיניסטיים? אם כן — Flow פשוט יותר וצפוי יותר מ-Agent.
  4. האם נדרש סטייל/פורמט/התנהגות עקבית שאינה משתנה? שווה לשקול Fine-Tuning.
  5. האם יש כמה כלים חיצוניים שצריך לחבר בפרוטוקול אחיד וניתן לשימוש חוזר? MCP.
  6. האם יש ידע מוגדר היטב (קוד/תבניות) שלא צריך להיות בכל prompt? Skill.

🧠 שאלות ראיון נפוצות

ש: מתי תעדיף Flow קבוע על פני Agent אוטונומי?

ת: כשהתהליך ידוע וחזרתי מראש — Flow צפוי יותר, קל יותר ל-debug וזול יותר; Agent שמיועד למשימות קבועות הוא overkill ומוסיף סיכון (cost explosion, state ניהול) בלי תועלת.

ש: מה ההבדל המעשי בין Fine-Tuning ל-RAG כשרוצים שהמודל 'ידע' מידע חדש?

ת: RAG מוסיף ידע עדכני בזמן ה-inference דרך שליפה — קל לעדכן ושקוף; Fine-Tuning משנה את משקלי המודל וסטייל ההתנהגות, לא מתאים להזרקת עובדות עדכניות ומחייב אימון חדש לכל עדכון.
