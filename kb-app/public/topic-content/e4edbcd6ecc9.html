📋 הגדרה

Plugin הוא תיקייה מנוהלת-גרסאות (versioned folder) שמאגדת skills, sub-agents, hooks, slash commands, ו-MCP servers ליחידה אחת להתקנה — כך שיכולות agent הופכות לאקוסיסטם חבילות (package ecosystem), בדומה למודול npm.

🏛️ מבנה Plugin

  • plugin.json — מטא-דאטה, גרסה, נקודות כניסה (entry points).
  • תיקיות: skills/, agents/, commands/, hooks/.
  • התקנה ממרקטפלייס: /plugin marketplace add ולאחר מכן /plugin install <name>.
  • עובד גם ב-Claude Code וגם ב-SDK (אופציית plugins).

🎯 מתי לבחור Plugin

  • כשיש workflow הנדסי חזרתי (review, release, onboard) שרוצים לארוז ולשתף כיחידה אחת.
  • כשרוצים ניהול גרסאות (versioning) ויכולת שיתוף קלה בין צוותים/פרויקטים.

✅ יתרונות

  • מאגד את כל מה שצריך (skills+agents+hooks+commands+MCP) ליחידה אחת מותקנת.
  • ניהול גרסאות מובנה — אפשר לעדכן/לשחזר גרסת plugin.
  • ניתן לשיתוף כמו מודול תוכנה רגיל (git repo, marketplace).

❌ מגבלות

  • תוספת שכבת abstraction — דורש הבנה של כל תת-הרכיבים (skills/agents/hooks/MCP) כדי לתחזק plugin.

🔄 קשר לנושאים אחרים

Plugin הוא שכבת-העל (top layer) במחסנית ה-agent המלאה: Plugin layer → Skill layer → Sub-agent layer → SDK/Runtime → Tool layer. Hooks חוצים את כל השכבות כ-guardrails דטרמיניסטיים.

🧠 שאלות ראיון נפוצות

ש: מה ההבדל בין Plugin ל-Skill בודד?

ת: Skill הוא יחידת ידע/נוהל בודדת (SKILL.md + קבצים). Plugin הוא יחידת חבילה גבוהה יותר שיכולה לאגד כמה skills, sub-agents, hooks, ו-MCP servers יחד כ-workflow מלא, עם ניהול גרסאות והתקנה דרך marketplace.

ש: מדוע plugin.json מכיל הגדרת mcpServers ולא רק skills/agents?

ת: כי plugin שלם מאגד את כל הרכיבים הדרושים להפעלת workflow — אם ה-workflow צריך גישה חיה ל-GitHub API למשל, ה-MCP server הרלוונטי מוגדר בתוך אותו plugin כך שההתקנה תיתן את כל התלויות בפעולה אחת.
