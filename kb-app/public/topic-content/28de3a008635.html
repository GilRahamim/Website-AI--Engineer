הגדרה

טכניקת רגולריזציה שעוצרת את האימון ברגע שה-validation loss מפסיק להשתפר, במקום להריץ מספר epochs קבוע מראש. הקריטריון נקבע לפני תחילת האימון — לא מסתכלים על התוצאות ואז מחליטים איפה לעצור.

איך זה עובד

  • 1. בסוף כל epoch מחשבים את ה-loss על סט ה-validation.
  • 2. אם ה-loss השתפר ביותר מ-ε ביחס לטוב ביותר עד כה — שומרים את משקלי המודל ומאפסים את מונה הסבלנות.
  • 3. אם לא השתפר — מקדמים את מונה הסבלנות באחד.
  • 4. כשהמונה מגיע ל-patience, עושים break על לולאת ה-epochs.
  • 5. טוענים בחזרה את המשקלים הטובים ביותר שנשמרו — לא את האחרונים.

פירוש פרמטרים

שימושים עיקריים

  • מניעת Overfitting בלי לשנות את הארכיטקטורה או להוסיף רגולריזציה.
  • חיסכון בזמן חישוב — לא מבזבזים שעות GPU על epochs שרק מזיקים.
  • קביעה אוטומטית של מספר ה-epochs, שהוא היפר-פרמטר שקשה לנחש מראש.
  • מלווה כמעט תמיד ReduceLROnPlateau — קודם מורידים את α, ורק אם גם זה לא עוזר, עוצרים.

יתרונות

  • כמעט חינם — לא מוסיף פרמטרים ולא מאט את האימון.
  • עובד עם כל ארכיטקטורה וכל אופטימייזר.
  • מספק אוטומטית את המודל בנקודת ה-generalization הטובה ביותר.

חסרונות / מגבלות

  • דורש סט validation נפרד — בדאטה קטן זו עלות משמעותית.
  • רגיש ל-patience: קצר מדי יעצור על רעש מקומי; ארוך מדי יבזבז זמן.
  • עקומת validation רועשת (batch קטן) יכולה לגרום לעצירה מוקדמת מדי.
  • אם משווים בין שתי שיטות אימון, חובה להסכים מראש על קריטריון העצירה — אחרת ההשוואה מוטה.

קוד לדוגמה (PyTorch)

import copy, torch

best_val_loss = float('inf')
patience, patience_counter = 10, 0
best_state = None

for epoch in range(200):
    model.train()
    for X_batch, Y_batch in train_loader:
        optimizer.zero_grad()
        loss = criterion(model(X_batch), Y_batch)
        loss.backward()
        optimizer.step()

    model.eval()
    with torch.no_grad():
        val_loss = sum(criterion(model(X), Y).item()
                       for X, Y in val_loader) / len(val_loader)

    if val_loss < best_val_loss - 1e-4:          # שיפור אמיתי
        best_val_loss = val_loss
        best_state = copy.deepcopy(model.state_dict())
        patience_counter = 0
    else:
        patience_counter += 1
        if patience_counter >= patience:
            print(f"Early stopping at epoch {epoch}")
            break

model.load_state_dict(best_state)                # המודל הטוב ביותר, לא האחרון

שאלות ראיון נפוצות

ש: למה Early Stopping נחשב רגולריזציה?

ת: כי הוא מגביל את הקיבולת האפקטיבית של המודל. ככל שמאמנים יותר, המשקלים גדלים והמודל לומד יותר פרטים ספציפיים לסט האימון. עצירה מוקדמת שומרת את המשקלים קטנים יותר — אפקט דומה ל-L2 regularization.

ש: למה חייבים לשמור את המשקלים הטובים ביותר ולא להסתפק באחרונים?

ת: כי כשעוצרים אחרי patience epochs ללא שיפור, המודל כבר patience epochs בתוך אזור ה-overfitting. המשקלים האחרונים גרועים יותר מאלה שהיו בנקודת המינימום של ה-validation loss.

ש: על איזה סט מודדים — validation או test?

ת: validation בלבד. שימוש ב-test set לקביעת נקודת העצירה הוא זליגת מידע: המודל מכויל לסט שאמור לשמש רק להערכה סופית בלתי-תלויה.
