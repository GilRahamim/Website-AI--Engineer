📋 הגדרה כללית

מדדי הערכה ל-retrieval בודקים האם, וכמה טוב, מערכת השליפה (vector search / hybrid search) מצליחה להחזיר את המסמכים הרלוונטיים ביותר לשאילתה — בטרם שלב ה-LLM. הערכה שיטתית מאפשרת השוואת אסטרטגיות chunking, מודלי embedding, ולוגיקת re-ranking, ומונעת מצב שבו בעיית retrieval גרועה מוסווה ככשל LLM.

1️⃣ Recall@k

📋 מודד אם לפחות מסמך רלוונטי אחד מופיע בתוך top-k התוצאות שהוחזרו. קריטי כשאסור לפספס תוכן רלוונטי (למשל מערכות retrieval רפואיות).

2️⃣ Precision@k

📋 מחשב את שיעור המסמכים הרלוונטיים מתוך top-k התוצאות. מתמקד באיכות (לא רק בנוכחות) של מה שהוחזר — חשוב כשרק מספר מצומצם של chunks נכנס ל-LLM.

3️⃣ MRR — Mean Reciprocal Rank

📋 מודד באיזה מיקום בדירוג מופיע המסמך הרלוונטי הראשון. נותן פרס למערכות שמציבות תוצאות רלוונטיות בראש הרשימה — נפוץ במערכות QA וחיפוש.

כאשר rankq הוא המיקום של המסמך הרלוונטי הראשון לשאילתה q.

4️⃣ nDCG — Normalized Discounted Cumulative Gain

📋 מעריך את איכות הדירוג המלא, ומשקלל מסמכים רלוונטיים לפי מיקומם — מתאים להגדרות עם רלוונטיות מדורגת (graded relevance) ולא רק בינארית.

כאשר reli הוא ציון הרלוונטיות של המסמך במיקום i, ו-IDCG@k הוא ה-DCG של הדירוג האידיאלי.

✅ מתי עדיף איזה מדד

  • Recall@k — כשהעדיפות היא לא לפספס תוכן רלוונטי, גם במחיר רעש.
  • Precision@k — כשחלון ההקשר של ה-LLM מוגבל וכל chunk 'תופס מקום יקר'.
  • MRR — כשחשוב שהתשובה הטובה ביותר תהיה ממש בראש הרשימה (UX של חיפוש).
  • nDCG — כשיש דירוג מרובה-רמות (graded relevance) ורוצים להעריך את כל הרשימה, לא רק את החלק העליון.

❌ מגבלות

  • כל המדדים תלויים בקיומו של ground truth (שאילתות בנצ'מארק עם תשובות ידועות) — איסוף הנתון הזה דורש מאמץ.
  • Recall/Precision בגרסתם הבסיסית הם בינאריים — לא מבחינים בין 'רלוונטי קצת' ל'רלוונטי מאוד' (לכך משמש nDCG).

💻 מימוש בקוד

def recall_at_k(relevant, retrieved, k):
return any(item in relevant for item in retrieved[:k])
def precision_at_k(relevant, retrieved, k):
top_k = retrieved[:k]
return sum(1 for item in top_k if item in relevant) / k
def mrr(relevant, retrieved):
for rank, item in enumerate(retrieved, start=1):
if item in relevant:
return 1 / rank
return 0
# Simulate a test case
relevant_docs = {&quot;doc2&quot;, &quot;doc4&quot;}

print(f&quot;Precision@3: {precision_at_k(relevant_docs, retrieved_docs, k=3):.2f}&quot;)
print(f&quot;MRR: {mrr(relevant_docs, retrieved_docs):.2f}&quot;)

🧠 שאלות ראיון נפוצות

ש: מה ההבדל בין Recall@k ל-Precision@k?

ת: Recall@k בודק אם לפחות תוצאה רלוונטית אחת נכללת ב-top-k (נוכחות), בעוד Precision@k בודק איזה אחוז מה-top-k הוא בכלל רלוונטי (איכות/ניקיון).

ש: מתי תבחר nDCG על פני MRR?

ת: כשיש יותר ממסמך רלוונטי אחד ורלוונטיות מדורגת (לא בינארית) — nDCG מעריך את כל הרשימה המדורגת, בעוד MRR מתמקד רק במיקום של הראשון.
