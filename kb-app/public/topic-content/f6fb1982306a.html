📋 הגדרה

HNSW הוא אלגוריתם state-of-the-art לחיפוש שכנים קרובים בקירוב (Approximate Nearest Neighbor — ANN), המבוסס על גרף רב-שכבתי (multi-layer proximity graph). הוא עומד בבסיס מנועי החיפוש של FAISS, Qdrant, Weaviate ו-Milvus (Malkov & Yashunin, 2016).

⚙️ איך זה עובד

  1. בונים גרף מרובה-שכבות: השכבות העליונות דלילות (long-range links), השכבה התחתונה (Layer 0) צפופה ומכילה את כל הנקודות.
  2. חיפוש מתחיל בנקודת כניסה (entry point) בשכבה העליונה.
  3. Greedy descent search — בכל שכבה מתבצע 'דילוג' לשכן הקרוב ביותר, ואז יורדים שכבה ומחזרים על התהליך.
  4. כשמגיעים ל-Layer 0, מתבצע חיפוש מדויק יותר בין השכנים הקרובים ביותר בפועל.
  5. תכונת 'עולם קטן' (small-world): קישורים ארוכי-טווח מקצרים את אורך מסלול החיפוש לסדר גודל לוגריתמי.

🎯 שימושים עיקריים

  • אינדקס לחיפוש סמנטי בקנה מידה גדול (מיליוני וקטורים) בזמן אמת.
  • הליבה של מסדי נתונים וקטוריים: FAISS, Qdrant, Weaviate, Milvus, pgvector.

✅ יתרונות

  • recall גבוה במהירות חיפוש מהירה ביחס לשיטות ANN אחרות.
  • מתאים מאוד לאינדקס שחי כולו בזיכרון (in-RAM).

❌ חסרונות / מגבלות

  • צריכת זיכרון גבוהה — האינדקס חי כולו ב-RAM.
  • זמן בנייה (build time) של הגרף יכול להיות משמעותי באוספי דאטה גדולים.
  • Trade-off מובנה: recall מהיר מול זיכרון וזמן בנייה.

💻 קוד לדוגמה (FAISS + Sentence Transformers)

from sentence_transformers import SentenceTransformer
import faiss
documents = [
&quot;Crohn's disease is a chronic condition affecting the gut.&quot;,
&quot;Biologics and steroids are common treatments.&quot;,
&quot;Dietary fiber can support gut health.&quot;,
]
bi_encoder = SentenceTransformer('all-MiniLM-L6-v2')
doc_embeddings = bi_encoder.encode(documents, convert_to_numpy=True)
dimension = doc_embeddings.shape[1]
index = faiss.IndexHNSWFlat(dimension, 32)   # M = 32
index.hnsw.efConstruction = 200
index.add(doc_embeddings)
query_embedding = bi_encoder.encode([&quot;How to treat Crohn's?&quot;], convert_to_numpy=True)
index.hnsw.efSearch = 64
D, I = index.search(query_embedding, k=3)

🧠 שאלות ראיון נפוצות

ש: מה התפקיד של השכבות העליונות בגרף HNSW?

ת: הן דלילות ומכילות קישורים ארוכי-טווח, ומאפשרות 'לדלג' מהר על פני המרחב הווקטורי לפני שמתבצע חיפוש מדויק יותר בשכבה התחתונה הצפופה.

ש: מה ההבדל בין efConstruction ל-efSearch?

ת: efConstruction קובע את רוחב החיפוש בזמן בניית הגרף (משפיע על איכות האינדקס), בעוד efSearch קובע את רוחב החיפוש בזמן שאילתה (משפיע על recall מול latency בזמן אמת).
