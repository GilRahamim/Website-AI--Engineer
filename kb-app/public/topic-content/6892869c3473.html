📋 הגדרה

Anthropic Skills ושרתי MCP הם שני primitives משלימים להרחבת יכולות Claude: Skill הוא חוברת הוראות מקומית שנטענת לפי-דרישה, ו-MCP הוא שרת חיצוני שחושף כלים/משאבים בפרוטוקול סטנדרטי. הבחירה הנכונה תלויה במידת ה-statefulness, השיתוף הנדרש, ורמת ה-typing.

🎯 מתי לבחור Skill

  • המשימה היא פרוצדורה חזרתית — "איך עושים X כאן?"
  • רוצים לשלוח הוראות + כמה סקריפטים יחד, בלי שירות נפרד.
  • הלוגיקה מקומית וחסרת-state.
  • רוצים אפס תשתית לתחזוקה.

🎯 מתי לבחור MCP

  • צריך אינטגרציה חיה (Slack, Jira, DB פנימי, API פרודקשן).
  • מספר agents/IDEs/משתמשים משתפים את אותה משטח-כלים.
  • נדרש auth, rate limits, תצפיתיות, או session state.
  • סכמות הכלים צריכות להיות typed ומאומתות באופן מחמיר.

🏛️ הרכבה: Skills + Agents + MCP

השלושה מרכיבים יחד stack מלא: שכבת Skill מספקת playbooks (SKILL.md, סקריפטים, תבניות), שכבת Agent מריצה את הלופ (נימוק → קריאת כלי → תצפית → חזור), ושכבת Tool (כולל שרתי MCP, Bash, file tools, web fetch) מבצעת את העבודה בפועל. Skill אומר ל-agent מה לעשות; ה-agent מחליט מתי; הכלים (כולל MCP) מבצעים.

✅ עקרון מרכזי

Skills ו-MCP אינם תחרותיים אלא משלימים: Skill = playbook, MCP = live tools. לרוב התשובה הנכונה היא לשלב את שניהם. Skill יכול לקרוא לכלי MCP, ושרת MCP יכול לכלול תיקיית Skills.

🧠 שאלות ראיון נפוצות

ש: מתי הרכבת Skills+MCP טובה יותר משימוש באחד בלבד?

ת: כשה-playbook (סדר הפעולות, פורמט התשובה) הוא לוגי-מקומי וחזרתי, אבל חלק מהשלבים דורשים גישה לאינטגרציה חיה ומאובטחת (כגון DB פרודקשן) — Skill מנהל את הפרוצדורה ו-MCP מספק את הגישה החיה לנתונים/שירותים.

ש: מדוע MCP פחות מתאים למאות כלים בהשוואה ל-Skills?

ת: MCP טוען את כל סכמות הכלים מראש, כך שעלות ה-token גדלה לינארית עם מספר הכלים. Skills טוענים רק name+description בכל עת, וגוף ההוראות נטען רק לפי דרישה — מאפשר עשרות Skills בעומס מינימלי.
