📋 הגדרה

Embedding API הוא שירות שמהפוך טקסט לוקטור מספרי בעל ממד גבוה (high-dimensional vector), כך שמשמעות סמנטית של הטקסט נשמרת במרחב הווקטורי — טקסטים בעלי משמעות קרובה יקבלו וקטורים קרובים.

🔍 השירותים המרכזיים

  • OpenAI — text-embedding-3-small (זול, מהיר, איכותי) ו-text-embedding-3-large (טוב יותר למסמכים ארוכים ורב-לשוניים).
  • Cohere — embed-v3, מותאם ל-retrieval ול-classification, תמיכה רב-לשונית.
  • Voyage AI — embeddings מותאמים לתעשייה, ביצועים מובילים.
  • HuggingFace — מודלים open-source כמו all-MiniLM-L6-v2, bge-base, intfloat/e5-base, להרצה מקומית.

🎯 שימושים עיקריים

  • חיפוש סמנטי (semantic search) ושאלות-תשובה על מסמכים (RAG).
  • סיווג טקסטים, clustering, ומציאת דמיון בין מסמכים.

💻 קוד לדוגמה — OpenAI Embedding API

import os
from openai import OpenAI
client = OpenAI(api_key=os.getenv(&quot;OPENAI_API_KEY&quot;))
response = client.embeddings.create(
model=&quot;text-embedding-3-small&quot;,
input=&quot;Crohn's disease management&quot;
)
embedding = response.data[0].embedding
print(&quot;Embedding len:&quot;, len(embedding))  # 1536

✅ יתרונות

  • מאפשר חיפוש לפי משמעות ולא רק לפי מילות מפתח.
  • ניתן להשתמש במודלים מקומיים (open-source) לסביבות ללא אינטרנט / רגישות פרטיות.

❌ חסרונות / מגבלות

  • חובה להשתמש באותו מודל embedding לשאילתה ולמסמכים — אי-עקביות פוגעת בדיוק.
  • מודלים פרופריטריים (OpenAI, Cohere, Voyage) תלויים ב-API חיצוני ויוצרים עלות שוטפת.

🧠 שאלות ראיון נפוצות

ש: מה קורה אם נשתמש במודל embedding אחד לשאילתה ובמודל אחר למסמכים?

ת: וקטורים ממודלים שונים חיים במרחבים גאומטריים שונים — דמיון קוסינוס בין שניהם לא משקף משמעות אמיתית, וה-retrieval יהיה שגוי.

ש: מתי תבחר מודל embedding מקומי (HuggingFace) על פני API בתשלום?

ת: בסביבות עם רגישות פרטיות, air-gapped, או כשעלות/latency של API חיצוני אינם מתאימים לקנה המידה.
