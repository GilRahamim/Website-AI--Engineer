📋 הגדרה

Guardrails הם מכניזמים המגבילים ומכוונים את התנהגות ה-Agent כדי לבנות אפליקציות AI אחראיות — מונעים תוכן רעיל, חוסר רלוונטיות לדומיין, ו-hallucinations.

🔍 שלושה סוגי Guardrails מרכזיים

סוגתיאורתרחיש
Domain Relevanceמענה רק על שאלות רלוונטיות לדומיין ה-Agent (ביטוח, בנקאות וכו')Agent בנקאי שמתבקש לכתוב שיר על חתולים → מסרב ומכוון לשאלות פיננסיות
Toxicity Controlזיהוי וסינון תוכן פוגעני/לא הולםתמיכה שמקבלת קללה → de-escalation במקום להחזיר/להגביר את העלבון
Hallucination Preventionמניעת תשובות מפוברקות-אך-משכנעות"מה היתרה בחשבון שלי?" → ניתוב ל-API מאובטח, לא ניחוש מספר

⚠️ זיהוי הצורך ב-Guardrails

  • Agent חשוף לקלט משתמש לא מבוקר (UGC) — סיכון לתוכן רעיל/הזרקת prompt.
  • Agent נדרש לדייקנות עובדתית גבוהה (כספים, רפואה, משפט) — סיכון hallucination גבוה.
  • Agent פועל בדומיין צר (תמיכה ספציפית-מוצר) ועלול "לסטות" לנושאים לא רלוונטיים.

🛠️ איך מיישמים

  • רשימת topics מורשים/חסומים (banned_topics / allowed_topics) שנבדקת לפני מענה.
  • הודעת סירוב אחידה ועקבית (refusal_message) למקרים חסומים.
  • ניתוב שאלות עובדתיות-קריטיות ל-API מאובטח במקום לתת ל-LLM "לנחש".

💻 קוד לדוגמה — חסימת נושאים ב-CrewAI

# guardrails_topics_policy.yaml
banned_topics:
- politics
refusal_message: &gt;
Sorry — I can't discuss politics. Please ask about another topic
(e.g., MCP, RAG, CrewAI, SMART-on-FHIR, IBD, ME/CFS, Fibromyalgia).
@agent
def researcher(self) -&gt; Agent:
return Agent(
config=self.agents_config['researcher'],
verbose=True,
tools=[TopicsRefusalTool()],
)

🧠 שאלות ראיון נפוצות

ש: מה ההבדל בין Domain Relevance ל-Hallucination Prevention?

ת: Domain Relevance בודק אם השאלה בכלל רלוונטית לתחום ה-Agent (לפני יצירת תשובה); Hallucination Prevention מבטיח שתשובות עובדתיות מבוססות במקור אמין (API/מסמך) ולא מפוברקות — שתי שכבות הגנה שונות לחלוטין.

ש: מדוע de-escalation עדיף על התעלמות/חסימה מוחלטת בתרחיש Toxicity?

ת: התעלמות מוחלטת עלולה להשאיר את המשתמש מתוסכל ולתפוס כחוסר-מענה; de-escalation מכיר בתחושת המשתמש בלי להגיב לעלבון עצמו, ומכוון אותו חזרה לפתרון בעיה — שומר על חוויית שירות תקינה.
