🛠️ Validation עם Pydantic / PydanticAI

PydanticAI משתמש במודלי Pydantic כדי לאמת ולפרסר פלט LLM לאובייקטי Python מטופסים. מבטיח type safety, שדות חובה, הודעות שגיאה ברורות על פלט לא תקין, ותמיכה בסכמות מקוננות.

💻 קוד לדוגמה

from pydantic import BaseModel, Field, ValidationError
import json
class PatientSummary(BaseModel):
name: str
age: int = Field(..., ge=0)
diagnosis: str
summary: str
def validate_output(output: str) -&gt; PatientSummary:
try:
data = json.loads(output)
return PatientSummary.model_validate(data)
except (json.JSONDecodeError, ValidationError) as e:
print(&quot;Validation failed:&quot;, e)
raise

✅ יתרונות

  • מאפשר pipelines אוטומטיים מלאים: LLM → JSON מאומת → DB/API.
  • מצמצם טיפול ידני בשגיאות פרסור (parsing) בהמשך התהליך.

❌ חסרונות / מגבלות

  • Prompt-only validation חשוף ל'סטייה' — המודל עלול להחזיר טקסט נוסף סביב ה-JSON.
  • אכיפת סכמה מחמירה מדי עלולה לגרום לכשל מלא כשהמודל לא מצליח למלא שדה חובה.

🔄 קשר לנושאים אחרים

פלט מבני הוא הבסיס שמאפשר ל-Function Calling ול-Agents לפעול בצורה אמינה — בלי שכבת validation, שגיאות פרסור ישברו את שרשרת הכלים.

🧠 שאלות ראיון נפוצות

ש: למה model-native schema (function calling) עדיף בדרך כלל על prompt-only?

ת: כי האכיפה מתבצעת בזמן הדגימה (decoding) של המודל עצמו לפי ה-schema, ולא רק כהוראה בטקסט — מה שמקטין משמעותית את הסיכוי לפלט שלא תואם לפורמט המבוקש.

ש: מה הערך המוסף של PydanticAI מעבר ל-json.loads רגיל?

ת: json.loads רק מפרסר טקסט JSON גולמי בלי לבדוק טיפוסים/שדות חובה. PydanticAI מוסיף שכבת type safety מלאה — מאמת טיפוסים, mandatory fields, וטווחי ערכים (כמו age >= 0), עם הודעות שגיאה ברורות לכשל.
