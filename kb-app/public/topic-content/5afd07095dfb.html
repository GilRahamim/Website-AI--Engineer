✍️ Prompt Engineering ל-Agents

  • הוראות כלים מפורשות — שמות כלים מדויקים, פורמטי קלט/פלט עקביים (לא "tool1" אלא "search_web").
  • תבניות ReAct / Plan-and-Execute — מבנה Thought/Action/Action Input/Observation/Final Answer.
  • עידוד נימוק שלב-אחר-שלב ("Think step by step before choosing a tool") — משפר דיוק בבחירת כלים.
  • בקרת התנהגות — הגבלת hallucinations ושימוש לרעה בכלים, אכיפת זרימת נימוק.
  • בדיקה ושיפור — A/B testing לניסוחים שונים, מעקב טוקנים/איכות פלט, כיוונון למודלים שונים (GPT, Claude, Gemini).
  • תכנון prompt מודולרי — הפרדה בין תיאורי כלים, דוגמאות אינטראקציה, והוראות משימה-ספציפיות.

⚠️ מלכודות נפוצות (Pitfalls)

מלכודתתיאורפתרון מומלץ
Prompt Injection & Tool Abuseמשתמשים יוצרים קלטים ששוברים לוגיקת כלים או חולצים התנהגות פנימיתסניטציה של קלט + אכיפת סכמה מחמירה
Infinite Reasoning LoopsAgent נתקע במחזורי Thought→Action→Observationמספר איטרציות מקסימלי / תנאי יציאה מוקדמים
Tool Misuseבחירת כלי שגוי, פורמט קלט לא תקין, פירוק פלט שבורתיאורי כלים טובים יותר, validation, תגובות מבניות
Missing/Leaky MemoryAgent stateless שוכח שלבים קודמים או משתמש בהקשר מיושןמודולי memory (conversation buffer, vector store)
Latency Bottlenecksבעיקר ב-multi-agent / RAG workflowsקריאות כלים אסינכרוניות, caching, paralellism

🧠 שאלות ראיון נפוצות

ש: למה Tool Accuracy נמדד בנפרד מ-Task Success?

ת: Agent יכול להשיג את המטרה הסופית (Task Success) במקרה, גם אם בחר כלים לא אופטימליים בדרך — מדידת Tool Accuracy בנפרד חושפת בעיות תהליך שלא בהכרח באות לידי ביטוי בתוצאה הסופית.

ש: מה ההבדל בין הגנה מפני Prompt Injection לבין Guardrails לנושאים (Domain Relevance)?

ת: הגנת Prompt Injection מתמקדת במניעת קלטים זדוניים ששוברים את לוגיקת המערכת או חולצים מידע פנימי; Domain Relevance Guardrails מגבילים את התוכן הלגיטימי שה-agent מסכים לדון בו — שתי שכבות הגנה משלימות, לא חופפות.
